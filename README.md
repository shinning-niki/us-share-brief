# 美股收盘简报（云端自动化）

美东交易日收盘后，北京时间 **07:40** 自动抓取美股收盘数据，生成手机端简报页面并推送到手机。
**全程运行在 GitHub Actions 云端，本机关机不影响。**

这是 [a-share-brief](../a-share-brief) 的美股版：**同一套方法论，按美股的市场结构换了变量**。

## 为什么是云端

WorkBuddy 内置定时任务绑定在本机进程上，电脑休眠/关机即停止调度。
本项目把调度、取数、渲染、推送全部搬到 GitHub Actions，唯一的本机依赖是首次部署。

## 调度时间的推导（不是随手定的）

| 环节 | 时间 |
|---|---|
| 美股收盘（美东 16:00） | 北京 04:00（夏令时）/ 05:00（冬令时） |
| 盘后交易结束（美东 20:00） | 北京 08:00 / 09:00 |
| **本简报触发** | **北京 07:40**（UTC 23:40，周一至周五） |

两个坑：

1. **cron 在北京时间周二至周六触发**，不是周一到周五。因为北京周一早上对应的美东是周日——不开市，推出去的会是上周五的重复数据。
2. **不能用「北京日期 −1」硬算美东日期**。美东夏令时切换会让偏移在 12/13 小时之间跳，本脚本用 `zoneinfo` 做时区换算，两端窗口按美东 09:30 / 16:00 锚定，自动适配。

## 链路

```
GitHub Actions (cron 23:40 UTC = 北京次日 07:40，周一至周五)
   │
   ├─ scripts/fetch_brief.py   抓数据 → data/brief.json
   │    ├─ 腾讯行情    五大指数 / 11 个 GICS 板块 ETF / MAG7 / 宏观 ETF（单请求批量取）
   │    ├─ 东财资讯    「美股收盘 / 美股复盘 / 美股三大指数」（相当于 A 股的「收评」）
   │    ├─ 新浪 7×24   盘中事件型快讯（美东 08:30→20:00 严格封口）
   │    ├─ 东财研报    海外/美股策略研报（机构名 + 核心判断 + 原文链接）
   │    └─ data/history.json  SPY+QQQ 成交额（用于计算放缩量）
   │
   ├─ 交易日判定：用「行情时间的美东日期」对齐「应收盘日」，假日自动识别 → 休市直接退出
   ├─ scripts/build_brief.py   渲染 → dist/index.html（单文件、移动优先、深色）
   ├─ GitHub Pages             部署页面
   └─ scripts/notify.py        推送到手机（飞书 / Bark / Server酱 / PushPlus / Telegram）
```

## 板块设计：与 A 股版哪里不同

A 股版看「指数分化 + 量能 + 题材轮动」；美股的结构不同，所以变量换了三处：

| 变量 | A 股版 | 美股版 | 为什么换 |
|---|---|---|---|
| 板块 | 东财概念板块（几百个） | 11 个 GICS 行业 SPDR ETF | 美股没有「概念板块」等价物，行业 ETF 才是机构真实的仓位语言 |
| 广度 | 上涨家数（交易所收评披露） | RSP（标普等权）− SPY（市值加权） | 美股无公开涨跌家数接口。等权与市值加权的差值，能直接量化「指数是不是几只巨头抬出来的」 |
| 波动 | 成交额放缩 | 标普日内振幅 + 成交额放缩 | VIX 的中文实时源不可得（腾讯 usVIX 停在 2026-09），日本内振幅更可靠 |
| 特有 | — | **MAG7 权重股** | 七巨头是美股指数方向的直接决定者，必须单列 |

## 简报版块（页面自上而下）

| 序号 | 板块 | 内容 |
|---|---|---|
| 1 | 指数条 | 道指 / 纳指 / 标普500 / 罗素2000 / 费半 + 振幅 + 广度 + 成交额，合并为一条信息带 |
| 2 | 板块强弱 | 11 个 GICS 行业 ETF 涨跌分列条形可视化（涨红左对齐、跌绿右对齐） |
| 3 | 权重股 MAG7 | 七巨头涨跌幅 + 均值较标普的高低 |
| 4 | 盘面归因 | 结构 / 广度 / 量能 / 主线 / 催化 / 宏观 六段判断 |
| 5 | 今日要闻 | 最多 3 条，标题 + 摘要 + 原文链接；**分数不够就不凑数** |
| 6 | 明日展望 | 海外策略研报：机构 + 标题 + 核心判断 + 原文链接 |

**归因的原则**（沿用 A 股版）：数字只在顶部出现一次，归因段落只给判断、不复述数字；因果关系一律标注为「相关性对齐，不能直接认定为涨跌原因」。抓不到研报时明确写"不做方向性判断"，不用模板话术填充。

红涨绿跌（与 A 股简报一致，降低两套简报间的认知切换成本）。

## 代理标的说明

| 展示名 | 实际标的 | 原因 |
|---|---|---|
| 罗素2000 | IWM | 腾讯行情无 usRUT，IWM 是罗素2000 的跟踪 ETF |
| 费城半导体 | SMH | 腾讯行情无 usSOX，SMH 是半导体行业 ETF |

页面上这两个标的**只显示涨跌幅、不显示点位**，避免把 ETF 价格误读成指数点位。

## 已知边界

- **GitHub Actions cron 有 5–20 分钟延迟**，07:40 触发通常 07:45–08:00 出结果。
- **美东假日自动识别**：靠「行情日期 vs 应收盘日」对齐判断，不需要维护假日表；误判风险只在行情接口挂掉时出现，那时会直接报"未取到行情"而不是硬编一份简报。
- **要闻可能只有 2 条**：设了最低分门槛（10 分），低于门槛的不用来填满 3 条。
- **资讯窗口两端封口**：起点美东 09:30 前 1 小时、终点美东 20:00。不封口会把「今天下午的新闻」错配给「昨晚的行情」——这是设计时刻意防的一个坑。
- 数据源均为公开接口，上游限流或改版会降级（缺条不编造）。
- **GitHub 60 天无提交会自动停用定时工作流**：本项目每日回写 `data/history.json`，天然规避。

## 部署（首次，约 3 分钟）

```bash
GH_TOKEN=github_pat_xxx BARK_URL=https://api.day.app/你的Key python3 scripts/deploy_github.py
```

脚本会自动：建仓库 → 上传全部文件 → 开启 Pages（Source = GitHub Actions）→ 写入 `BARK_URL` Secret → 触发一次运行。

**Token 必须带 `repo` + `workflow` 两个权限**。只给 `repo` 时，写入 `.github/workflows/*` 会返回 **404**（伪装成"文件不存在"），看起来像环境问题，实际是权限问题。

推送渠道（可多配，写在仓库 Settings → Secrets and variables → Actions）：

| Secret | 渠道 | 怎么拿 |
|---|---|---|
| `FEISHU_WEBHOOK` | 飞书 | 群 → 设置 → 群机器人 → 添加自定义机器人 → 复制 Webhook |
| `BARK_URL` | Bark（iOS，最省事） | App Store 装 Bark → 复制形如 `https://api.day.app/你的Key` |
| `SCT_KEY` | Server酱（微信） | sct.ftqq.com 微信扫码 |
| `PUSHPLUS_TOKEN` | PushPlus（微信） | pushplus.plus 微信扫码 |
| `TG_BOT_TOKEN` + `TG_CHAT_ID` | Telegram | @BotFather 建 bot，@userinfobot 取 chat id |

## 本地手动运行

```bash
python3 scripts/fetch_brief.py     # 抓数据
python3 scripts/build_brief.py     # 生成 dist/index.html
open dist/index.html               # 本地预览
BARK_URL="https://..." python3 scripts/notify.py   # 测试推送
```

无第三方依赖，纯标准库（Python 3.9+，`zoneinfo` 需 3.9 及以上）。
